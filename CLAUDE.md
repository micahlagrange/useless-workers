# Morphis

A LÖVE 11 game (Lua 5.1), played on desktop and in the browser through love.js.

## Working on it

- `main` is the main line: only an accepted epic's merge goes there (see below); epic work goes on `epic/<slug>`. Every push to `main` runs CI (`.github/workflows/build.yml`): tests, makelove builds, then butler pushes to https://multivoxmuse.itch.io/morphi about two minutes later. Itch can sit in "processing" and refuse new pushes for a while; it clears up by itself.
- `src/version.lua` holds the build number shown on the title screen. Set it to `git rev-list --count HEAD` + 1 in each commit you push, so a stale page can be told from a new one.
- Commit as Micah Turner <turner.micah@gmail.com>.
- Tests: `./test.sh` (luajit when installed, else `python3 tst/run.py`, which needs `pip install lupa`). Keep code Lua 5.1 compatible. `tst/arcade_test.lua` plays every arcade level's solutions with the real AI.

## The backlog and how it ships

Micah's backlog for every game lives in Jam Hub, https://claude.ai/artifact/VejqPPeU1baL1Z7KsuQDHZ: Morphis's are the documents in collection `items` with `jamId` `morphi`. Everything there is an **epic** (there are no bugs any more; a bug is a small epic). The full contract, fields and who sets what are in `%USERPROFILE%\.claude\skills\game-jam
eferences\epic-workflow.md`; it wins over this summary. An epic has `title`, `description` (at most 50 words), `stories` [{id, text, done}] (at most 200 words together), `priority` 1-4, `status`, `images`, `artifacts` [{label, url, build?, createdAt}], `branch`, `build`, `note`, `testSteps`, and when needed `forMicah` or `problem`. Micah's review comments sit in collection `reviews` ({itemId, text, images, status open/fixed, fixNote, fixedBuild}).

Statuses: `draft` (Micah writing it; leave it alone) → `ready` (Micah: build it) → `working` (Claude is on it) → `testing` (Claude: a test artifact plays it) → `accepted` (Micah) → `shipped` (Claude, after verifying itch). Also `blocked` (Claude needs Micah: `forMicah` says exactly what) and `dropped` (Micah: delete its branch and test artifacts, then set `cleanedAt`).

- **Ready**: take the next one (lowest `priority` number, then oldest) in a fresh worktree from `origin` (never Micah's checkout, never a folder with someone else's uncommitted work) on `epic/<slug>`, merging `origin/main` in first. Fix its open `reviews` first, then build as many stories as fit, proving each with the unit tests and a fast headless run (game speed up, `Worker:update` stepped in a loop, or a test that plays the level) rather than real time. Push the epic branch only. Ambiguity is not a reason to stop: make a reasonable call and say so in `note`; set `blocked` only when Micah truly must decide.
- **Testing**: never without a test artifact (see Seeing it run) built from the exact pushed commit, listed in `artifacts` (re-publish to the epic's first artifact url), with `build`, `note` and `testSteps` (3-6 numbered plain lines: where to open it, what to do, what to see, what failure looks like). Code changed but no artifact → `problem` {kind: "build-failed"} and the epic stays `ready`. Micah plays it, ticks stories `done` himself, and either adds reviews and sets `ready` again or sets `accepted`. Never tick stories and never edit his text.
- **Accepted**: in a fresh worktree off `origin/main`, merge the epic branch into `main` keeping both sides' intent (never drop other work, never force-push `main`), set `src/version.lua`, run the tests, push `main` (that publishes to itch). Then verify: CI for that commit succeeded including its itch publish step, and the itch page serves the new build (its upload date is after the push; the title screen's `build N` is the new one). Only then set `shipped` with `mergedAt`/`shippedAt`, write the Jam Hub blog post with the itch link, and draft the devlog (below). Not yet verifiable → stays `accepted` with `problem` {kind: "deploy-unverified"}; a conflict or CI failure → `problem` with what failed.
- CI builds and tests every branch but only pushes `main` to itch.
- Things only Micah can do that belong to no one epic go in collection `actions` as {text, jamId: `morphi`, itemId?, createdAt, done: false}, never as a question you wait on. Read an epic's or review's image with the Artifact tool (`read`, `url` the Jam Hub, `path` = its id); `enc: base64` means base64 text to decode.
- Every merge to `main` gets a **devlog post on the itch page** (game id 2546949), written for a player: a one or two sentence summary of the build; a paragraph or two more only when a change is big (how the new thing works, what to expect); up to 2 or 3 screenshots when they show something; then bulleted release notes, one specific change per line ("morphis face the correct way when digging", "initial farming mechanic introduced, may be buggy!"). Devlogs live on itch only, never in git: write the post as `devlog/build-N.md` (first line `# title`, `![](path)` lines for screenshots; the folder is gitignored scratch, do not commit it) and send it as a **draft**, never published, because Micah publishes his own devlogs: `node %USERPROFILE%\.claude\skills\game-jam\scripts\itchdevlog.mjs post --game 2546949 --post devlog/build-N.md --draft`, then tell him the draft is waiting. itch has no devlog API; the script drives the editor in its own signed-in Chromium profile, and `itchdevlog.mjs login` is the one-time sign-in only Micah can do. If the profile is not signed in, add a For Micah action asking for the login and keep the post text in the action; never type his password. Format details: the skill's `references/itch-devlog.md`.

## Seeing it run

- Web build: makelove packs the committed tree, so commit first. Then `makelove lovejs` (or `python -m makelove lovejs`), `python3 tools/patch_lovejs.py makelove-build/lovejs/morphis-lovejs.zip`, and unzip it somewhere outside `makelove-build` (a server running inside it locks the folder on Windows). Serve that folder with `python3 -m http.server 8000`: the game is at `http://localhost:8000/morphis/`.
- Screenshots: `node tools/drive.js steps.json outdir [--phone]` plays the build headless with Playwright (software GL, no GPU needed) and saves the shots its steps ask for. love.js takes a click's position from the last mouse move, so the script hovers before each click. On the title screen, Enter twice starts the first level.
- Test artifacts (every epic at `testing` has one): build from the committed tree as above (prefer building locally over downloading CI's artifact, which can fail on the account's egress limit), then `tools/artifact_prep.sh <unzipped>/morphis out/` lays the build out for a claude.ai Artifact (which will not serve `.data` files); publish `out/index.html` with the other files beside it: game.js, love.js, love.wasm and gamedata.wasm (the two wasm files as application/wasm), theme/bg.png and theme/love.css. Re-publish to the same artifact URL for a later build of the same epic.
- Name a test page `Morphis <EPIC> b<build> - <what's new>`: pass it as the third argument of `tools/artifact_prep.sh`, which sets the `<title>` tag, the only thing that names the artifact.

## Run stats

- A run's audit log (`src/stats.lua`) leaves the game as text: EXPORT (the DEV button on the top bar, or the screen at the end of any game: game over, end of year, level clear or failed) shows the JSON with COPY and DOWNLOAD; in a browser it sits in a selectable text box over the game. Micah pastes it into the run viewer, https://claude.ai/artifact/MkPjsiF2xNFFwgc3SRYMMf (source `tools/stats_viewer.html`, published with `capabilities: {db: {}, user: {}}`), which saves it in its database as `<exported>-<first words of the note>-b<build>.json`.
- To bring saved runs onto this machine: ArtifactData `list` on the run viewer, collection `runs`, `out_dir` `stats/inbox`; then `python tools/stats_archive.py --clean` writes each one to the archive, `C:/Users/sixst/Documents/morphis-stats-archive`, under that name. Read them there with `tools/stats_report.py`.
- Run exports, sims and graphs are never committed: `stats/` is ignored but for its README.

## Voice

Morphis are little blobs in a meadow: whimsical, soft and a bit silly, never fantasy, frontier or grim. Every player-facing string (labels, news, alerts, hints, milestones, the README, devlogs) uses the meadow words: little blobs, the bunch, the home nest, stash, basket, nest, sticks, leaves, grass, shinies, digging, gatherer, digger, caretaker, grumbles, newcomers. Never use: dwarf, wilds, settler, migrant, lumber, chop, fell, log(s), stone, gold, ore, mine/mining/miner, camp, hardship, quit, the band. Internal identifiers (ROLE_LUMBERJACK, CARGO_LOGS, 'mine', world.breakroom, hires, quarter) may keep their old names until a story renames them; only what the player reads must change. `tst/words_test.lua` scans the string tables and a scripted free play log for the banned words.
